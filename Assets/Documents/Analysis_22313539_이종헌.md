## 1. 데이터 소스 로드

* **Use Case Name**: Load Data Source
* **Summary**: 게임 시스템 기획자가 캐릭터 스탯, 스킬 수치, 환경 변수 등이 저장된 외부 데이터 파일을 시스템으로 불러오는 기능이다. 로드된 정보는 시뮬레이션 환경 구축의 기초가 되며, 주요 액터인 게임 시스템 기획자와 보조 액터인 전투 데이터 파일 간의 상호작용으로 이루어진다. 정상적으로 데이터를 불러오는 기본 시나리오와 파일 형식 오류 또는 데이터 누락 시 경고를 출력하는 확장 시나리오를 포함한다.
* **Primary Actor**: 게임 시스템 기획자
* **Secondary Actors**: 전투 데이터 파일
* **Precondition**: 시뮬레이터 시스템이 구동 중이어야 하며, 시스템이 접근 가능한 경로에 유효한 데이터 파일(ScriptableObject 등)이 존재해야 한다.
* **Postcondition**: 시뮬레이터의 메모리에 전투 수치가 할당되어 유스케이스 시나리오 구성을 위한 준비가 완료된다.
* **Scenario**:
    * **Main Success Scenario**
        1. 게임 시스템 기획자가 데이터 로드 메뉴를 선택한다.
        2. 시스템은 파일 탐색 창을 출력한다.
        3. 게임 시스템 기획자가 로드할 전투 데이터 파일을 선택한다.
        4. 시스템은 선택된 파일을 읽어 내부 데이터 모델로 변환한다.
        5. 시스템은 데이터 로드 완료 메시지를 화면에 표시한다.
    * **Extension Scenario**
        * 4a. 선택된 파일의 형식이 시스템 규격과 일치하지 않는 경우:
            1. 시스템은 데이터 형식 오류 메시지를 출력한다.
            2. 기본 시나리오 2단계로 돌아간다.
        * 4b. 파일 내 필수 수치(체력, 공격력 등)가 누락된 경우:
            1. 시스템은 데이터 누락 항목을 경고 창으로 알린다.
            2. 유스케이스를 종료한다.

## 2. 전투 시나리오 선택

* **Use Case Name**: Select Battle Scenario
* **Summary**: 게임 시스템 기획자가 사전에 정의된 4 vs 4 전투 상황(시나리오) 중 하나를 선택하여 테스트 환경을 구축하는 기능이다. 기획자가 유닛을 직접 배치하지 않고 정형화된 시나리오를 선택하면 시스템이 자동으로 아군과 적군 유닛을 배치한다. 정상적으로 시나리오를 활성화하는 과정과 선택을 취소하는 상황을 다룬다.
* **Primary Actor**: 게임 시스템 기획자
* **Secondary Actors**: 없음
* **Precondition**: Use Case #1(Load Data Source)가 성공적으로 완료되어 시스템에 유닛 및 스킬 정보가 존재해야 한다. Use Case #1(Load Data Source)
* **Postcondition**: 특정 전투 시나리오가 활성화되어 시뮬레이션 실행이 가능한 상태가 된다.
* **Scenario**:
    * **Main Success Scenario**
        1. 게임 시스템 기획자가 시나리오 선택 메뉴를 활성화한다.
        2. 시스템은 로드된 데이터에 기반한 4 vs 4 시나리오 목록을 출력한다.
        3. 게임 시스템 기획자가 특정 전투 시나리오를 선택한다.
        4. 시스템은 선택된 시나리오에 따라 아군 유닛 4개와 적군 유닛 4개를 가상 진영에 배치한다.
        5. 시스템은 배치 완료 상태를 인스펙터 창에 표시한다.
    * **Extension Scenario**
        * 3a. 기획자가 시나리오 목록에서 '취소'를 선택하는 경우:
            1. 시스템은 시나리오 선택 창을 닫고 이전 상태를 유지한다.

## 3. 유닛별 행동 가중치 설정

* **Use Case Name**: Set Behavior Weights
* **Summary**: 게임 시스템 기획자가 각 유닛이 전투 중 수행할 행동(공격, 방어, 스킬 등)의 발생 확률을 조정하는 기능이다. 확률 값을 입력받아 AI 행동 패턴을 정의하며, 입력값이 유효하지 않을 경우 재입력을 요구하는 시나리오를 포함한다.
* **Primary Actor**: 게임 시스템 기획자
* **Secondary Actors**: 없음
* **Precondition**: 시나리오 선택이 완료되어 시뮬레이션 대상 유닛들이 확정된 상태여야 한다. Use Case #2(Select Battle Scenario)
* **Postcondition**: 시뮬레이션 연산 시 각 유닛이 참조할 행동 확률 변수값이 업데이트된다.
* **Scenario**:
    * **Main Success Scenario**
        1. 게임 시스템 기획자가 행동 가중치 설정 창을 연다.
        2. 시스템은 배치된 유닛별 스킬 및 행동 목록을 출력한다.
        3. 게임 시스템 기획자가 유닛별 행동 확률 값을 입력한다.
        4. 시스템은 입력된 확률 값의 유효성을 검사한다.
        5. 시스템은 설정된 가중치를 데이터 모델에 저장한다.
    * **Extension Scenario**
        * 4a. 입력된 확률의 총합이 100%를 초과하거나 음수 값을 입력한 경우:
            1. 시스템은 수치 오류 메시지를 출력하고 해당 입력 칸을 강조한다.
            2. 기본 시나리오 3단계로 돌아간다.

## 4. 시뮬레이션 제어

* **Use Case Name**: Start/Pause/Stop Simulation
* **Summary**: 게임 시스템 기획자가 시뮬레이션 연산의 시작, 일시정지, 중지 명령을 수행하여 전체 프로세스의 생명주기를 직접 관리하는 기능이다. 명령에 따라 연산 루프가 구동되거나 중단되며, 설정 미완료 시 실행을 제한하는 시나리오가 존재한다.
* **Primary Actor**: 게임 시스템 기획자
* **Secondary Actors**: 없음
* **Precondition**: 시나리오 선택 및 행동 가중치 설정이 모두 완료되어 연산 준비가 끝난 상태여야 한다. Use Case #2(Select Battle Scenario), Use Case #3(Set Behavior Weights)
* **Postcondition**: 시뮬레이션의 실행 상태가 기획자의 조작 결과에 따라 변경된다.
* **Scenario**:
    * **Main Success Scenario**
        1. 게임 시스템 기획자가 시뮬레이션 '시작' 버튼을 클릭한다.
        2. 시스템은 설정된 조건으로 연산 루프를 가동한다.
        3. 게임 시스템 기획자가 필요 시 '일시정지' 버튼을 클릭한다.
        4. 시스템은 현재 연산 프레임을 동결하고 대기한다.
        5. 게임 시스템 기획자가 '중지' 버튼을 클릭한다.
        6. 시스템은 모든 연산을 종료하고 결과 수집 단계로 전환한다.
    * **Extension Scenario**
        * 1a. 시나리오나 가중치가 설정되지 않은 상태에서 시작을 시도할 경우:
            1. 시스템은 '설정 미완료' 경고를 출력하고 버튼을 비활성화한다.

## 5. 시뮬레이션 실행

* **Use Case Name**: Execute Simulation
* **Summary**: 시스템이 기획된 4 vs 4 전투 로직을 반복 수행하여 승률 및 잔여 HP 등의 원천 데이터를 생성하는 핵심 연산 기능이다. 대량의 전투를 반복 수행하는 기본 시나리오와 연산 중 발생하는 예외 상황을 처리하는 확장 시나리오로 구성된다.
* **Primary Actor**: 게임 시스템 기획자
* **Secondary Actors**: 없음
* **Precondition**: Use Case #4(Start/Pause/Stop Simulation)를 통해 시작 명령이 전달되어야 한다. Use Case #4(Start/Pause/Stop Simulation)
* **Postcondition**: 분석 가능한 원천 통계 데이터가 시스템 내부에 생성된다.
* **Scenario**:
    * **Main Success Scenario**
        1. 시스템은 그래픽 출력을 제외한 순수 전투 로직 연산을 시작한다.
        2. 시스템은 각 턴의 유닛 행동 결과를 데이터 버퍼에 기록한다.
        3. 시스템은 설정된 반복 횟수(예: 10,000회)가 완료될 때까지 연산을 수행한다.
        4. 시스템은 연산 완료 후 생성된 원천 데이터의 요약을 화면에 표시한다.
    * **Extension Scenario**
        * 1a. 연산 도중 무한 루프나 로직 예외가 감지되는 경우:
            1. 시스템은 해당 전투 회차를 강제 종료하고 예외 로그를 남긴다.
            2. 시스템은 기획자에게 오류 발생 지점을 알리고 다음 시뮬레이션 회차로 넘어간다.

## 6. 결과 저장 및 외부 연동

* **Use Case Name**: Export Results
* **Summary**: 시뮬레이션 실행을 통해 생성된 데이터를 CSV 또는 JSON 파일 형식으로 저장하고 외부 분석 툴과 공유하는 기능이다. 기획자가 형식을 선택하여 저장하는 과정과 저장 공간 부족 등 실패 상황에 대한 처리를 포함한다.
* **Primary Actor**: 게임 시스템 기획자
* **Secondary Actors**: 외부 분석 툴
* **Precondition**: 시뮬레이션 실행이 완료되어 내부 데이터 버퍼에 결과 수치가 존재해야 한다. Use Case #5(Execute Simulation)
* **Postcondition**: 외부 도구에서 읽기 가능한 통계 파일이 로컬 저장소에 생성된다.
* **Scenario**:
    * **Main Success Scenario**
        1. 게임 시스템 기획자가 '결과 내보내기' 버튼을 클릭한다.
        2. 시스템은 저장할 파일 형식(CSV/JSON)을 요청한다.
        3. 게임 시스템 기획자가 원하는 형식을 선택한다.
        4. 시스템은 내부 데이터를 해당 형식으로 직렬화하여 파일로 저장한다.
        5. 시스템은 저장 완료 알림과 함께 파일 경로를 제공한다.
    * **Extension Scenario**
        * 4a. 저장 경로에 쓰기 권한이 없거나 저장 공간이 부족한 경우:
            1. 시스템은 저장 실패 원인을 알리고 다른 경로를 선택하도록 유도한다.
            2. 기본 시나리오 2단계로 돌아간다.
