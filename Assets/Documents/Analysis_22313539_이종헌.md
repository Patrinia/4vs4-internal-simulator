# 1. Introduction

## 1.1 Summary
본 프로젝트는 유니티 엔진 내부에서 동작하는 4 vs 4 턴제 전투 시스템 전용 밸런스 시뮬레이터 개발을 목적으로 한다. 기존의 수동 테스트나 외부 도구를 이용한 방식에서 발생하는 시간적 비효율 문제도 해결할 수 있다. 또한 실제 게임과 동일한 C# 전투 로직을 활용하고 그래픽 연산을 배제하여 고속 시뮬레이션을 수행함으로써, 복잡한 전투 변수 간의 상호작용을 빠르고 편리하게 객관적인 데이터로 추출한다. 이를 통해 제작자의 직관에만 의존하던 기존 밸런싱 방식의 한계를 극복하고, 프로젝트의 완성도를 높일 수 있는 신뢰도 높은 검증 환경을 구축하고자 한다.

---

## 1.2 Business Goals
* **객관적인 밸런싱 근거 확보**: 단기간에 수만 번의 전투 데이터를 생성하여 승률, 잔여 HP 비율 등 통계적 지표를 확보함으로써 정교한 수치 조정의 근거를 마련한다.
* **로직 일관성 및 신뢰성 유지**: 실제 게임 코드를 100% 동일하게 활용하여 시뮬레이션 결과와 실제 플레이 간의 오차를 원천적으로 차단한다.
* **분석 프로세스의 효율화**: 시뮬레이션 결과를 CSV 또는 JSON 등 외부 분석 도구와 연동 가능한 형식으로 저장하여, 전문적인 시각화 및 정밀한 데이터 분석 프로세스를 지원한다.
* **개발 비용 및 피드백 루프 단축**: 수동 테스트에 소요되는 시간적 비용을 획기적으로 절감하고, QA 단계에서의 논리 무결성 검토를 자동화하여 수동 검증에 소요되는 시간과 인력을 절감하고 전체 개발 주기를 단축한다.

## 2.2 Use Case Description
### 2.2.1 파티 편성
* **Use Case Name**: Form Party
* **Summary**: 게임 시스템 기획자가 전투 시뮬레이션에 참여할 아군 및 적군 유닛을 배치하고, 각 유닛이 사용할 스킬(고정 이동기, 일반 스킬, 필살기 등)을 장착하여 전투 진형의 기초 데이터를 구성하는 기능이다.
* **Primary Actor**: 게임 시스템 기획자
* **Secondary Actors**: 유닛 및 스킬 정적 데이터 (UnitData, SkillData ScriptableObject)
* **Precondition**: 시스템 내부에 유효한 유닛과 스킬 데이터베이스가 로드되어 있어야 한다.
* **Postcondition**: 기획자가 설정한 조합이 `PartyRoster` 메모리에 저장되어 시뮬레이션 진형 배치의 준비가 완료된다.
* **Scenario**:
    * **Main Success Scenario**
        1. 게임 시스템 기획자가 파티 편성 메뉴에 진입한다.
        2. 시스템은 현재 선택 가능한 유닛 및 스킬 리스트 UI를 출력한다.
        3. 게임 시스템 기획자가 아군 및 적군 슬롯에 유닛을 드래그하여 배치한다.
        4. 게임 시스템 기획자가 각 배치된 유닛에 규격에 맞는 스킬들을 할당한다.
        5. 게임 시스템 기획자가 편성 완료 버튼을 클릭한다.
        6. 시스템은 조합을 `PartyRoster`에 저장하고 편성 완료 메시지를 출력한다.
    * **Extension Scenario**
        * 4a. 스킬 장착 개수 제한을 초과한 경우:
            1. 시스템은 스킬 장착 제한 개수 초과 경고창을 출력한다.
            2. 시스템은 해당 스킬 장착 시도를 취소하고 기본 시나리오 4단계로 돌아간다.
        * 5a. 진영에 유닛이 1명도 배치되지 않은 경우:
            1. 시스템은 진영 빈칸 경고를 출력한다.
            2. 기본 시나리오 3단계로 돌아간다.

### 2.2.2 시뮬레이션 환경 설정
* **Use Case Name**: Configure Simulation
* **Summary**: 게임 시스템 기획자가 전투가 진행될 횟수(최대 10,000회 이상)와 무한 루프 방지를 위한 최대 허용 라운드 수 등 시뮬레이션의 거시적 파라미터를 입력하는 기능이다.
* **Primary Actor**: 게임 시스템 기획자
* **Secondary Actors**: 없음
* **Precondition**: `PartyRoster`에 최소 1회 전투를 진행할 파티 편성 데이터가 존재해야 한다.
* **Postcondition**: 입력된 파라미터가 `SimulationManager`와 `BattleManager`의 환경 변수로 주입된다.
* **Scenario**:
    * **Main Success Scenario**
        1. 게임 시스템 기획자가 환경 설정 메뉴를 활성화한다.
        2. 시스템은 반복 횟수 및 최대 라운드 입력 폼을 제공한다.
        3. 게임 시스템 기획자가 시뮬레이션 반복 횟수와 최대 라운드를 입력하고 저장 버튼을 누른다.
        4. 시스템은 입력된 수치의 유효성을 검사한다.
        5. 시스템은 환경 설정이 정상적으로 적용되었음을 화면에 표시한다.
    * **Extension Scenario**
        * 4a. 입력된 수치가 유효하지 않은 경우 (예: 반복 횟수가 0 이하, 문자가 섞임 등):
            1. 시스템은 수치 오류 경고 메시지를 출력한다.
            2. 시스템은 입력 필드를 초기화하고 기본 시나리오 3단계로 돌아간다.

### 2.2.3 대규모 시뮬레이션 가동
* **Use Case Name**: Execute Simulation
* **Summary**: 설정된 환경 변수를 바탕으로, 그래픽 렌더링을 제외한(Headless) 고속 턴제 전투 연산을 지정된 횟수만큼 반복 실행하는 핵심 기능이다.
* **Primary Actor**: 게임 시스템 기획자
* **Secondary Actors**: 없음
* **Precondition**: 파티 편성과 환경 설정이 모두 완료되어 있어야 한다.
* **Postcondition**: 지정된 횟수만큼의 전투 연산이 모두 완료되어 데이터가 추출 준비 상태가 된다.
* **Scenario**:
    * **Main Success Scenario**
        1. 게임 시스템 기획자가 시뮬레이션 '시작' 버튼을 클릭한다.
        2. 시스템은 불필요한 UI와 그래픽 렌더링을 비활성화(Headless 모드 진입)한다.
        3. 시스템은 지정된 횟수만큼 `BattleManager`를 통해 전투 루프를 고속으로 반복 실행한다.
        4. 시스템은 모든 연산 완료 후 시뮬레이션 종료 알림을 출력하고 결과를 화면에 요약 표시한다.
    * **Extension Scenario**
        * 3a. 전투 중 힐/무적기 교착 상태로 무한 루프가 발생한 경우 (설정된 최대 라운드 도달):
            1. 시스템 내부의 `BattleManager`가 타임아웃 이벤트를 발생시킨다.
            2. 시스템은 해당 회차의 전투 결과를 무승부로 강제 정산하고 파일에 기록한다.
            3. 시스템은 중단 없이 즉시 다음 회차의 전투를 계속 진행한다.

---

### 2.2.4 시뮬레이션 강제 중단
* **Use Case Name**: Stop Simulation
* **Summary**: 대규모 연산이 진행되는 도중, 게임 시스템 기획자가 설정 오류를 발견하거나 시스템 과부하를 우려하여 진행 중인 시뮬레이션 코루틴을 즉시 강제 파괴하는 기능이다.
* **Primary Actor**: 게임 시스템 기획자
* **Secondary Actors**: 없음
* **Precondition**: Use Case #3(Execute Simulation)가 실행 중이어야 한다.
* **Postcondition**: 진행 중이던 전투 코루틴이 파괴되며, 중단된 시점까지의 데이터만 디스크에 보존된다.
* **Scenario**:
    * **Main Success Scenario**
        1. 게임 시스템 기획자가 시뮬레이션 진행 중 '강제 중단' 버튼을 클릭한다.
        2. 시스템은 즉시 `BattleManager`와 `SimulationManager`의 모든 전투 코루틴을 정지(StopAllCoroutines)시킨다.
        3. 시스템은 메모리에 남아있는 이벤트 구독을 해제하고 잔여 가비지를 청소한다.
        4. 시스템은 강제 중단 알림 메시지를 화면에 출력한다.
    * **Extension Scenario**
        * 2a. 시스템 과부하로 인해 중단 명령 버튼 입력 자체가 무시된 경우 (Freezing):
            1. 게임 시스템 기획자는 단축키나 외부 인터럽트를 통해 시스템에 강제 중단 신호를 보낸다.
            2. 시스템은 연산을 끊어내고 안전 모드로 복귀하여 데이터 손실 경고창을 띄운다.

### 2.2.5 밸런스 통계 데이터 추출
* **Use Case Name**: Export Balance Metrics
* **Summary**: 전투 종료 시마다 메모리 누수를 막기 위해 시스템이 실시간으로 써 내려간 CSV 요약 지표와 JSON 타임라인 파일을 게임 시스템 기획자가 확인하고 외부 폴더에서 접근할 수 있도록 돕는 기능이다.
* **Primary Actor**: 게임 시스템 기획자
* **Secondary Actors**: 운영체제 파일 시스템
* **Precondition**: 시뮬레이션이 최소 1회차 이상 진행되어 파일 스트림을 통해 지정된 경로에 데이터가 작성되어 있어야 한다.
* **Postcondition**: 게임 시스템 기획자가 추출된 데이터를 엑셀(Excel)이나 외부 분석 환경에서 열람할 수 있게 된다.
* **Scenario**:
    * **Main Success Scenario**
        1. 시스템은 전투가 끝날 때마다 실시간으로 CSV와 JSON 파일에 데이터를 기록(Flush)한다.
        2. 시뮬레이션 종료 후, 게임 시스템 기획자가 '로그 폴더 열기' 버튼을 클릭한다.
        3. 시스템은 OS 명령어를 호출하여 데이터가 저장된 폴더 창을 화면에 띄운다.
        4. 게임 시스템 기획자는 생성된 19칼럼 CSV 파일과 JSON 파일을 확인한다.
    * **Extension Scenario**
        * 1a. 하드디스크 용량 부족이나 권한 문제로 스트리밍 쓰기에 실패한 경우:
            1. 시스템은 파일 쓰기 오류를 감지한다.
            2. 시스템은 진행 중인 시뮬레이션을 즉시 정지하고 저장 공간 부족 경고 메시지를 출력한다.
            3. 게임 시스템 기획자가 해당 문제를 해결할 때까지 유스케이스는 중단된다.

## 3. Domain Analysis

### 3.1 Entity & Data 관련 클래스
시스템에서 다루는 핵심 데이터 구조와 개별 개체의 상태를 정의한다.

* **UnitData & SkillData**
    * 게임의 밸런스 기준이 되는 정적 데이터를 보관하는 ScriptableObject 컨테이너다.
    * 유닛의 기본 스탯과 각 스킬의 데미지, 부여할 상태이상, 성향(Tendency) 분포 등을 관리한다.
* **UnitControl**
    * 전장에 스폰된 개별 유닛의 실시간 생명주기를 담당한다.
    * 현재 체력, 속도, 음양 게이지, 활성화된 상태이상 리스트를 보관하며, 특정 패널티를 겪었는지 확인하는 플래그(`CorrosionExperienced`)와 지능(`IUnitBrain`)을 내부적으로 소유한다.
* **PartyRoster**
    * 파티 편성 단계에서 기획자가 구성한 조합의 스냅샷을 저장하는 메모리 저장소다.
    * 전투 종료 후 해당 장부에 실시간 체력 및 속성 수치를 덮어씌워 보존하는 역할을 수행한다.

### 3.2 Battle & Logic 관련 클래스
전투의 규칙 준수와 구체적인 수치 연산을 담당한다.

* **BattleManager**
    * 4 vs 4 전투의 핵심 코루틴 루프를 총괄 제어하는 지휘자(Orchestrator) 클래스다.
    * `ITurnSorter`를 통해 턴 대기열을 생성하고, 전멸 등 전투 종료 조건을 지속적으로 검사하여 승패를 확정짓는다.
* **CombatResolver**
    * 유닛의 뇌가 결정한 스킬 타겟팅 정보를 넘겨받아 실제 데미지와 회복량 등의 수치 연산을 단행한다.
* **StatusEffectManager**
    * 전투 라이프사이클(라운드 및 턴의 시작/종료)에 맞춰 상태이상(버프/디버프)을 갱신하고 적용하는 전담 관리자다.
    * 침식 과다 수치를 기준점(50)으로 복귀시키는 구제 로직 등 특수 룰을 정산한다.
* **FormationManager**
    * 1차원으로 구성된 진형(체스판)의 논리적 위치 데이터를 관리하고, 빈 공간이나 스왑(Swap) 등의 공간 연산을 지원한다.

### 3.3 Simulation & System 관련 클래스
전체 시뮬레이션 프로세스의 실행 환경을 제어한다.

* **SimulationManager**
    * 기획자가 설정한 반복 횟수(예: 1만 번)만큼 `BattleManager`를 점화시키는 최상위 루프 관리자다.
    * Headless 구동 환경을 제공하며, 시스템 과부하 우려 시 코루틴을 강제 종료(Stop)시킬 권한을 가진다.

### 3.4 Statistics & Export 관련 클래스
연산 결과의 수집, 모니터링 및 외부 데이터 연동을 지원한다.

* **BattleLogEvents**
    * 코어 매니저들이 서로 직접 참조하지 않도록 연결해 주는 단일 책임 이벤트 버스(Event Bus)다.
    * 전투 중 발생하는 모든 변화를 순수 데이터 형식으로만 브로드캐스트(Broadcast)한다.
* **BalanceDataExporter**
    * `BattleLogEvents`를 구독하여 실시간으로 통계 데이터를 수집하는 옵저버(Observer) 수집가다.
    * 19개 압축 칼럼으로 구성된 CSV 요약 지표와 JSON 계층형 타임라인 데이터를 `StreamWriter`를 통해 로컬 파일 시스템(`../SimulationLogs`)으로 실시간 출력하여 OOM(Out of Memory)을 방지한다.
* **BattleLogger**
    * 이벤트 버스를 구독하여 실제 게임 구동 시(또는 디버그 시) 콘솔에 전투 텍스트를 출력해 주는 아나운서 클래스다.

### 4.2 Unit Setting
플레이어측 유닛과 적측 유닛을 설정할 수 있다.
화면 중앙을 기준으로 상단이 플레이어측 유닛, 하단이 적측 유닛이다.

플레이어측 유닛은 어떤 유닛인지, 그 유닛이 어떤 기본 이동스킬을 지녔는지, 어떤 필살기를 장착할지, 어떤 기본스킬을 선택할 것인지 결정할 수 있다.

적측 유닛은 어떤 유닛인지만 결정할 수 있다.

게임 기획 상 플레이어는 유닛에게 배정된 다수의 스킬 중 스킬을 선택할 수 있지만
적 유닛의 경우 기획자가 사전에 지정해놓은 고정된 스킬셋을 가지기 때문에 이러한 차이점이 존재한다.

## 5. Glossary

* **피드백 루프 (Feedback Loop)**: 도출된 시뮬레이션 데이터를 기반으로 게임 수치를 수정하고, 이를 다시 시뮬레이터로 검증하는 반복적인 설계 최적화 과정이다.
* **프리징 (Freezing)**: 연산 부하로 인해 유니티 에디터 인터페이스가 일시적으로 중단되어 사용자의 입력을 받지 못하는 상태를 뜻한다.
* **결정론적 결과 (Deterministic Results)**: 난수 생성 규칙이 포함된 환경에서도 충분한 시행 횟수를 통해 통계 지표가 일정한 수치로 수렴하여 결과의 신뢰성을 확보하는 특성이다.
* **프리팹 (Prefab)**: 유니티 엔진에서 재사용 가능한 게임 오브젝트의 구성 정보를 저장한 에셋이며, 시뮬레이션 시 유닛 생성의 원형이 된다.
* **인스턴스화 (Instantiation)**: 메모리 상에 존재하는 클래스 정의나 프리팹 설계를 바탕으로 실제 동작 가능한 객체(Object)를 생성하는 행위다.
* **데이터 직렬화 (Serialization)**: 시스템 내부의 복잡한 개체 정보를 CSV나 JSON과 같은 외부 파일 형식으로 저장하거나, 반대로 읽어오기 위해 변환하는 과정이다.
* **논리 무결성 (Logical Integrity)**: 전투 시스템의 규칙과 데이터가 실제 게임 환경과 시뮬레이터 환경 사이에서 오차 없이 완벽하게 일치하는 상태를 의미한다.터가 실제 게임 환경과 시뮬레이터 환경 사이에서 오차 없이 완벽하게 일치하는 상태를 의미한다.
