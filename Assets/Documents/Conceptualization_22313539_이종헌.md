# 4 vs 4 턴제 전투 시스템 밸런스 시뮬레이터 기획서
## 1. Business Purpose

### 1) Project Background
전투 밸런스는 게임의 완성도와 플레이어의 재미를 결정짓는 핵심적인 요소다.
전투 난이도가 제작자의 의도와 다르게 설정될 경우 플레이어의 경험을 저해하며, 특정 전략의 고착화나 불공정함으로 인한 불쾌감을 유발할 수 있다.
특히 4 vs 4 전투 시스템은 캐릭터 간의 스킬 조합, 시너지, 상태 이상 효과 등 수많은 변수가 실시간으로 상호작용하는 복잡한 구조를 가지고 있다.
이러한 시스템에서는 제작자의 직관에만 의존하기에 명확한 한계가 존재하며, 데이터 기반의 객관적인 검증이 필수적이다.

### 2) Motivation
게임 밸런싱 작업은 수만 번 이상의 반복 테스트를 요구하지만, 시뮬레이터 없이 기획자가 직접 플레이하며 수치를 조정하는 방식은 물리적인 시간 소모가 너무 크고 통계적 신뢰성을 확보하기 어렵다.
기존의 유니티 외부(Python 등) 시뮬레이터 방식은 엔진의 C# 전투 로직을 타 언어로 중복 구현해야 하므로 로직 불일치 위험이 크고 유지보수 효율이 떨어진다.
반면 유니티 엔진 내부 시뮬레이터 방식은 실제 게임 코드를 100% 동일하게 활용하므로 결과의 정합성을 완벽히 보장한다.
또한 그래픽 렌더링과 물리 연산을 배제하여 고속 연산을 수행함으로써 게임 밸런싱의 피드백 루프를 혁신적으로 단축할 수 있다.

### 3) Goal
본 프로젝트의 목표는 유니티 내부에서 실제 게임 코드와 동일한 로직을 사용하여 단기간에 다수의 전투 데이터를 생성하고 객관적인 통계 지표를 확보하는 것이다.
플레이어 승률, 잔여 HP 비율, 전투 턴 수 등의 핵심 지표를 데이터화하여 정교한 수치 조정 근거를 마련한다.
특히 시뮬레이션 결과를 CSV 또는 JSON 등 외부 데이터 분석 툴과 연동 가능한 형식으로 저장하여, 전문적인 시각화 및 정밀 데이터 분석 프로세스를 구축하는 것을 최종 목표로 삼는다.

### 4) Target Market
본 시뮬레이터는 유니티 기반 게임 개발 과정에서 수치 조정과 밸런스 검증을 수행하는 게임 개발팀을 주요 대상으로 한다.
데이터 중심의 의사결정이 필요한 기획 단계뿐만 아니라, 전투 로직의 논리적 무결성을 사전에 검토해야 하는 QA(Quality Assurance) 단계에서도 효율적인 도구로 활용될 수 있다.

## 3. Use Case List
UML(Unified Modeling Language) 개념에 따라 시스템의 기능적 요구사항과 액터(Actor) 간의 관계를 정의한다.

### 1) 데이터 소스 로드 (Load Data Source)
* **Actor**: 게임 시스템 기획자
* **Description**: 기획자는 시뮬레이션의 기초가 되는 캐릭터 스탯, 스킬 수치, 환경 변수가 저장된 데이터 파일을 시스템에 로드한다.

### 2) 전투 시나리오 선택 (Select Battle Scenario)
* **Actor**: 게임 시스템 기획자
* **Description**: 사용자가 유닛을 직접 배치하지 않고, 사전에 정의된 특정 4 vs 4 전투 시나리오를 선택하여 시뮬레이션 환경을 즉각적으로 구성한다.

### 3) 유닛별 행동 가중치 설정 (Set Behavior Weights)
* **Actor**: 게임 시스템 기획자
* **Description**: 각 유닛이 전투 중 공격이나 방어 등 특정 스킬을 사용할 확률적 가중치를 설정하여 기획 의도에 부합하는 AI 행동 패턴을 정의한다.

### 4) 시뮬레이션 제어 (Start/Pause/Stop Simulation)
* **Actor**: 게임 시스템 기획자
* **Description**: 기획자는 시뮬레이션의 시작, 일시정지, 중지 명령을 수행하여 연산 프로세스의 생명주기를 직접 제어한다.

### 5) 시뮬레이션 실행 (Execute Simulation)
* **Actor**: 게임 시스템 기획자
* **Description**: 설정된 시나리오와 조건 하에서 엔진의 오버헤드를 배제한 순수 전투 로직 연산을 고속으로 반복 수행한다.

### 6) 결과 저장 및 외부 연동 (Export Results)
* **Actor**: 게임 시스템 기획자
* **Description**: 수행된 결과를 통계화하여 화면에 출력하고, 외부 분석 도구와 연동할 수 있도록 파일 형태로 저장한다.

## 4. Describe how to operate the use cases

### 1) 데이터 소스 로드 (Load Data Source)
* **Purpose**: 전투 로직 연산에 필요한 캐릭터 및 스킬의 기초 수치 데이터를 시스템에 확보하기 위함이다.
* **Approach**: 유니티 내부에 정의된 데이터 규격(ScriptableObject 등)을 시뮬레이터에 연결하여 데이터 모델로 변환한다.
* **Dynamics**: 시뮬레이션 환경 구축의 초기 단계에서 수행된다.
* **Goals**: 실제 게임 데이터와 시뮬레이터 데이터 간의 완전한 동기화를 목표로 한다.

### 2) 전투 시나리오 선택 (Select Battle Scenario)
* **Purpose**: 사용자가 수동으로 유닛을 배치하는 번거로움을 제거하고 정형화된 테스트 케이스를 신속하게 적용하기 위함이다.
* **Approach**: 기정의된 4 vs 4 전투 시나리오 리스트에서 검증 목적에 맞는 항목을 선택한다.
* **Dynamics**: 데이터 로드 완료 후 시뮬레이션 실행 전 단계에서 수행된다.
* **Goals**: 검증하고자 하는 특정 전투 상황을 즉각적으로 구성한다.

### 3) 시뮬레이션 제어 (Start/Pause/Stop Simulation)
* **Purpose**: 사용자가 원하는 시점에 연산을 수행하거나 중단하여 시뮬레이션 프로세스를 관리하기 위함이다.
* **Approach**: 유니티 에디터 UI의 제어 버튼(시작, 일시정지, 중단)을 클릭하여 연산 루프를 제어한다.
* **Dynamics**: 시뮬레이션 실행 중 실시간으로 상호작용한다.
* **Goals**: 연산 자원을 효율적으로 관리하고 필요한 시점의 데이터를 즉시 확인한다.

### 4) 결과 저장 및 외부 연동 (Export Results)
* **Purpose**: 생성된 데이터를 영구 기록하고 외부 전문 분석 툴과의 호환성을 확보하기 위함이다.
* **Approach**: 연산 완료 후 통계 데이터를 CSV/JSON 형식으로 변환하여 지정된 경로에 파일로 출력한다.
* **Dynamics**: 모든 시뮬레이션 회차가 종료된 후 최종적으로 수행된다.
* **Goals**: 데이터 기반의 정밀한 밸런스 조정 근거 자료를 확보한다.

## 5. Problem Statement

### 1) 유니티 메인 스레드 성능 관리
* 유니티 내부에서 대량의 연산을 수행할 경우 에디터의 응답성이 떨어지는 '프리징' 현상이 발생할 수 있다.
* 이를 방지하기 위해 Coroutine이나 C# Job System을 활용한 비동기 연산 처리가 필수적이다.

### 2) 로직 및 데이터 일관성 유지
* 실제 게임 전투 로직을 수정했을 때 시뮬레이터에도 즉각 반영되도록 설계해야 하며, 데이터 로드 시 형식 오류를 방지하는 검증 로직이 필요하다.

### 3) 방대한 시뮬레이션 데이터 관리
* 수만 번의 반복 시행으로 발생하는 방대한 로그 데이터가 메모리를 과도하게 점유하지 않도록 효율적인 데이터 버퍼링 및 저장 구조를 갖추어야 한다.

## 6. Glossary

### 1) 게임 시스템 기획자
* UML 관점의 액터(Actor)로, 게임의 수치적 밸런스와 논리적 규칙을 설계하고 시뮬레이터를 통해 이를 검증하는 실무자를 의미한다.

### 2) Unity (유니티)
* C# 언어를 사용하는 게임 개발 엔진으로, 본 프로젝트의 시뮬레이터가 구동되는 기반 환경이다.

### 3) ScriptableObject (스크립터블 오브젝트)
* 유니티에서 제공하는 대량의 데이터를 저장하기 위한 전용 컨테이너다. 유닛의 공격력, 체력 등 밸런스 수치를 저장하는 파일로 활용된다.

### 4) Inspector (인스펙터)
* 유니티 에디터에서 선택한 데이터나 오브젝트의 속성을 확인하고 수정할 수 있는 UI 설정 창이다.

### 5) Coroutine (코루틴)
* 실행을 일시 중단하고 나중에 다시 재개할 수 있는 기능이다. 시뮬레이션 연산을 프레임 단위로 나누어 수행하여 에디터 멈춤 현상을 방지한다.

### 6) C# Job System
* 멀티 코어 프로세서를 활용하여 코드를 안전하고 빠르게 병렬로 실행할 수 있게 해주는 유니티의 성능 최적화 기능이다.

### 7) 4 vs 4
* 플레이어 팀 유닛 4개와 적 팀 유닛 4개가 대치하는 본 시뮬레이터의 표준 전투 규모다.
